Started Tier 2 of the modeling plan (moderate features, 3-model comparison), per last session's roadmap.

## Decisions
- Tier 2 lives in its own notebook, `tier2_moderate_features.ipynb`, not appended to the main `champions_league_predictor.ipynb` — self-contained, just reads `elo.csv` from disk. Keeps the main notebook focused on the data pipeline, and later tiers can each get their own file.
- Chronological 80/20 train/test split by date quantile (not random) — never train on matches that happen after the ones being tested on.
- Season-opener rest gap (300+ days) gets flagged (`is_season_opener`) and filled with the league's normal in-season rest-day mean, not a fixed cap — "assume a season-opening team is about as rested as anyone on a normal matchday" rather than inventing an arbitrary number.
- Renamed `matches_played_this_season`/`matches_vs_mean` → `team_matches_played_this_season`/`team_matches_vs_mean` before they get `home_`/`away_` prefixed, so the result reads as "the home team's matches" and not "matches played at home."
- **Feature selection is being done deliberately, not automatically** — pruned to a "core only" set once mid-session without discussing it first; reverted. The full feature set stays in the notebook so importances can be reviewed and features chosen/transformed one at a time, not pruned wholesale by whichever accuracy number looks best on one 558-match test split.

## Problems & how we solved them
- `rest_days` had a long right tail (300-390 day gaps = off-season breaks, not real rest) that would have fed nonsense into the model → capped/flagged as `is_season_opener`, filled with the population's normal rest-day mean.
- Distribution chart for `matches_played_this_season`/`matches_vs_mean` was accidentally built from `model_df`'s `home_` columns only, silently dropping half the observations → fixed to pull from `team_log` (all team-match rows, home + away combined, all competitions).
- Tried to test "does a favorite being behind on games predict upsets" (a hypothesis about tired/rotated good teams) — couldn't: only 2-3 matches in the whole dataset have an elo-favorite meaningfully behind on matches played. Structural, not a data gap: favorites tend to be the teams *ahead* on fixtures (they're the ones also playing continental football), so the scenario is close to non-existent in this data as currently featured.

## What we learned (from real data)
- More engineered features made accuracy *worse*, not better, on a first pass: full 27-feature set (elo + form + rest + congestion + competition dummies + season-opener flags) scored 49.1%/50.2%/47.3% (LR/RF/XGB); a "core only" set (just elo + rolling form + elo momentum, 10 features) scored 51.1%/51.4%/49.8% — better on all three models. With ~2,200 training rows, the extra features were adding noise faster than signal. This was tested but **not adopted as the final feature set** — see Decisions above.
- Feature importance (Random Forest vs XGBoost, full feature set):
  - Both models broadly agree on the top ~18 features — elo (`elo_diff`, `home_elo_before`, `away_elo_before`, `avg_rating`) dominates, followed by a fairly even spread across rolling form (`ppg_5`, `gd_5`), elo momentum, side-specific PPG, fixture congestion (`team_matches_vs_mean`, `team_matches_played_this_season`), and rest days.
  - They **sharply disagree on the bottom 9**: the 7 one-hot competition dummies and the 2 `is_season_opener` flags. Random Forest rates these as near-zero (down to 0.0004); XGBoost spreads meaningfully more weight onto them (0.02-0.04 each) despite Random Forest (and the ablation above) suggesting they're not pulling real weight. Worth understanding *why* XGBoost disagrees before trusting either verdict blindly.
  - `elo_momentum_5` (a new feature this session — change in own Elo over the last 5 matches) pulled real, comparable weight to `ppg_5`/`gd_5` in both models — looks like a genuine addition, not noise.
  - Side-specific PPG (a team's rolling form computed only from their home matches, or only their away matches) only correlates 0.55 with the team's overall `ppg_5` — carries distinct information, not redundant.

## Maciej's thoughts / next steps for features
- Instead of 7 individual competition one-hot columns, try a single **local league vs. international** binary (domestic vs. Champions/Europa League) — directly targets the RF/XGBoost disagreement on the competition dummies, likely a cleaner signal than 7 near-useless columns.
- Plan going forward: review feature importance first, then deliberately choose per feature whether to keep / transform / drop / engineer differently for each model — not a blanket "drop everything below some importance threshold" pass.
